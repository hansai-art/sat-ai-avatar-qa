# 學生問題回報與工作台收錄

這份流程是公開問答網站與「AI 分身課程工作台」之間的回收契約。網站只負責把問題整理成可貼上的格式；課程留言是學生實際送出回饋的入口，工作台再把它和同一套 `qa_id` 資料對上。

## 學生使用流程

1. 在公開問答頁先看結論、步驟與相關題。
2. 仍未解決時，按「還沒解決」。
3. 選擇回報類型，補上作業系統、工具版本、卡住步驟與錯誤全文。
4. 先遮住 Token、API Key、密碼與個人資料，再複製內容。
5. 貼到[課程留言](https://sat.cool/course/201/comment)送出。

每筆回報都應保留公開頁面的 `qa_id`，例如 `qa-000001`。這是去重與追蹤用的識別，不把學員姓名放進公開 FAQ。

## 工作台處理契約

收到回報後，在「學員問答與排錯」留下：

| 欄位 | 用途 |
|---|---|
| `qa_id` | 對應既有公開題；找不到才標記待合併 |
| 原始問題與回報類型 | 保留觀察，不先改寫成結論 |
| 學員環境與錯誤 | 判斷是否是版本、權限或步驟差異 |
| `answer_status` | 尚未判斷、已回答、需要更新 |
| `material_status` | 教材是否需要修改或重新驗收 |
| `publication` | 草稿、已發布或已封存 |
| `sourceRefs` | 留言、官方文件、實測與版本證據 |

狀態順序是「收到 → 去重 → 查證 → 回覆 → 測試 → 發布」。回答完成不等於教材完成，也不等於已公開。

## 目前邊界

- 目前公開站是靜態網站，回報不會在背景自動送出，也沒有收集學生姓名、瀏覽紀錄或個人資料。
- 課程留言是目前正式的人工收件匣；未貼到留言的本機標記不會進入工作台。
- 若未來要做自動收件，必須另行設計儲存位置、權限、保留期限與個資告知，不能把本機 `localStorage` 當成中央資料庫。
- 公開答案仍只從 GitHub `src/content/questions/*.md` 發布；Page 與網站不各存一份正文。

## 速度驗收

- 首頁與全部問題頁先顯示靜態 HTML，不在首次載入時啟動 Pagefind。
- 只有輸入關鍵字、套用篩選或切換排序時才載入搜尋引擎與目錄。
- `_headers` 對 Astro、Pagefind、OCR 與問題頁設定邊緣快取；`build-info.json` 保持不快取，方便確認版本。
