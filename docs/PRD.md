## 1. 產品決策

建立一個讓學員先查既有答案的課程問答網站。每個問題有獨立網址、明確答案及適用條件，同時可從課程章節、工具與問題類型找到。相同答案只維護一份。

第一版採 Astro＋Markdown＋Pagefind，程式、經整理的公開問答與圖片放在 GitHub，網站由 Cloudflare Pages 發布，GitHub Pages 保留備用。學生使用一般瀏覽器，不需要 GitHub 帳號；編輯者才需要 repository 寫入權限。

Hans 已確認網站公開閱讀，學生不需登入。分工已確定：網站架構、資料格式與匯入由開發端負責；正式問答、圖片與影片連結由 Hans 提供。公開閱讀不代表原始學員留言、姓名或未處理截圖可以整包公開。

## 2. 問題與目標

### 2.1 要解決的問題

1. 問答散落在課程留言與群組，後來加入的學員很難找到。
2. 同一件事有不同說法，例如「Telegram 沒反應」與「TG 沒回應」，容易重複提問。
3. 長篇直播或群組摘要包含太多主題，找到文章後還要再找答案。
4. 問題與正在觀看的課程小節沒有連結。
5. 工具更新後，舊答案的適用情況不清楚。

### 2.2 產品目標

- 學員能用關鍵字、錯誤碼、工具名稱或章節找到已整理答案。
- 回答優先說明判斷與做法，再補原因、操作步驟及來源。
- Hans 可以直接分享某題網址，減少反覆重寫相同回答。
- 編輯者能新增、修訂、合併、封存問答，並追溯修改。
- 全部內容可以從 GitHub 匯出，不被單一線上資料庫綁住。

## 4. 使用者與角色

| 角色 | 主要任務 | 第一版權限 |
|---|---|---|
| 正在學習的學員 | 對照章節找操作問題 | 公開閱讀、搜尋、篩選、複製連結 |
| 已遇到錯誤的學員 | 貼錯誤碼找排除方法 | 同上 |
| Hans／指定編輯者 | 審核、修正、合併、發布問題 | GitHub 編輯與合併權限 |

## 5. 核心使用情境

| 情境 | 使用流程 | 預期結果 |
|---|---|---|
| 知道錯誤訊息 | 貼上錯誤碼或片段 → 選問題 | 先看到簡短判斷，再看到排錯步驟 |
| 只知道工具 | 選 Hermes Agent → 選錯誤排除 | 出現同時符合兩項條件的問題 |
| 對照課程 | 首頁直接篩選第 1 章 | 第一章全部問題集中顯示，不分小節 |
| 群組再次有人提問 | Hans 找到答案 → 複製問題網址 | 對方能直接閱讀該題 |
| 舊做法失效 | 編輯者修訂原題 → 重新發布 | 原網址保留，顯示更新時間與適用條件 |
| 搜尋沒有結果 | 查看清除篩選、改關鍵字及回課程提問提示 | 不顯示杜撰答案，也不聲稱已收到新問題 |

## 6. 內容分類與資料原則

### 6.1 三個主要分類

| 維度 | 規則 |
|---|---|
| 課程章節 | 先規劃 ch01～ch09；正式名稱、順序與小節由現行課綱匯入 |
| 工具 | 一題可標多個工具，例如 Hermes Agent＋Telegram |
| 問題類型 | 一題指定一個主要類型：安裝設定、帳號與付費、錯誤排除、操作方法、應用案例、課程與資源 |

「安裝設定」屬於問題類型，「Hermes Agent」屬於工具，兩者分開儲存。第一版每個篩選器單選，不同維度取交集；資料本身可以多章節、多工具。

沒有對應章節的共通題，可使用「跨章／通用」。尚未判定歸屬的題目保留草稿，不以「通用」掩蓋尚未整理。

工具初始候選包含 Hermes Agent、Obsidian、Telegram、ChatGPT、Claude、Gemini、GitHub、其他工具。這是分類建議，不代表以上工具各自有獨立課程章節。沒有文章的工具不必占據首頁。

### 6.2 一題一份正本

- 一筆問答以「一個可以清楚回答的問題」為單位。
- 同一留言有多個獨立問題，拆成多題；有共用原因的追問可留在同一題。
- 一題可出現在多個分類頁，使用同一個 ID 與網址。
- 作業系統不同但核心處理相同，採同題分段；原因或做法不同則拆題並互相連結。
- 重複問題合併到既有題，不靠新增相似標題累積題數。
- 章節改名、工具顯示名稱調整及問題改標題，不改既有問題網址。

### 6.3 每題需要的內容

必備：明確問題標題、簡短答案、正文、章節、工具、問題類型、建立與更新日期、公開來源說明、審核資訊。

依情況提供：小節、系統／版本、錯誤原文、截圖、影片連結、官方資料、相關問題、常見搜尋說法。非排錯題不強制填錯誤訊息，純觀念題不強制分成操作步驟。

### 7.1 搜尋細節

- 首頁的搜尋框以「搜尋問題、工具或錯誤訊息」提示。
- 關鍵字搜尋回傳問答卡片，包含標題、摘要／命中片段、分類、更新日期與待更新狀態。
- 同義說法由編輯者補入搜尋用語，不宣稱具備通用 AI 語意理解。
- 「TG」與「Telegram」等常見工具別名需有明確測例。
- 一頁 12 筆；預設有關鍵字時依相關性，無關鍵字時依最近更新。
- 可切換最近更新排序；變更查詢或篩選後回到第 1 頁。
- 搜尋條件保留在網址，可重新整理或分享。
- 不把學員輸入的內容送給 AI 服務；V1 不新增搜尋紀錄蒐集。

### 7.2 章節與小節細節

- 保留第 1～9 章入口，零筆時明確標示尚無整理問答。
- 正式名稱尚未提供時，規劃與演示可顯示「第 1 章」；不得杜撰章名。
- 上線前完成現行課綱核對；小節只使用已確認項目。
- 找不到有效的小節網址時，只提供課程首頁連結，不拼湊私人播放網址。
- 若課程日後增加章數，新增分類資料即可，介面不可把九章寫死在程式中。

### 7.3 媒體細節

- 圖片須能辨識操作介面及錯誤文字，有替代文字；無須每題配封面。
- 錯誤截圖另附可複製文字，以便搜尋及學員貼回 AI 排錯。
- 影片連結可附「從幾分幾秒開始」的文字提示；只在平台確實支援時使用時間跳轉 URL。
- V1 不上傳或代管完整影片，不保證所有網站都能嵌入播放。
- 影片摘要須用文字保存，搜尋只涵蓋已保存的文字，不自動辨識影片聲音。

「精選」由編輯者指定；沒有閱讀量資料時，不標示「最熱門」。

## 9. 維護流程與責任

### 9.1 新增

1. Hans 提供指定來源或問答；整理工作在非公開工作區進行。
2. AI 拆題、整理既有回答、建議分類、搜尋可能重複題。
3. 缺少答案、來源不明或相互矛盾者標記待處理，不補寫成確定答案。
4. Hans／編輯者確認文字、版本與公開範圍，處理圖片個資。
5. 產生合規 Markdown，經 PR 或 GitHub 編輯流程通過檢查後合併。
6. Cloudflare 自動建置部署，Actions 獨立檢查；確認公開網址與版本可用才回報已發布。

### 9.2 修訂與過期

- 只修字詞不改適用情境時，更新 updatedAt；不把 verifiedAt 自動改成今天。
- 重新核對步驟或官方文件，才更新 verifiedAt。
- 不確定是否適用時標「待更新」，保留上次確認日並暫停精選。
- 已被另一題取代時封存，保留原網址並指向替代問題。
- 如有外洩或有害內容，採移除而非公開保留歷史頁；Git 歷史亦須另行處理。

### 9.3 不依賴專用後台

V1 透過 GitHub 網頁編輯器或 AI 開發工具修改檔案。交接文件必須包含新增、圖片加入、改分類、合併題目及回復版本的方法。是否增設網頁管理後台，根據實際編輯負擔再決定。

## 10. 內容準則

- 標題描述具體問題，避免「救命」「不能用」等單獨作為標題。
- 摘要直接給判斷與做法；必要時明示「資料不足，需先確認某設定」。
- 不把某位學員的個案推廣成所有人都適用。
- 講師整理答案、官方說明與學員經驗要能分辨。
- API Key、驗證碼、帳單、帳號截圖及私人連結不可原樣公開。
- 公開題目預設不顯示提問者姓名；授權署名另行處理。
- 原始資料只有截圖而文字不清楚時，要求補充或留草稿。
- 改版資訊、價格、額度與操作介面以審核當時來源為準，記錄適用日期。
- 示範題必須清楚標示，正式模式會排除並檢查其未被索引。

| 初期資料量 | 建議先整理 30～50 題真實問答；此數量是導入建議，不是網站硬限制 |
| 容量測試 | 用 1,000 題合成公開測試資料驗證，不代表已達成容量或真實問答數 |
| 搜尋速度 | 依 Spec 約定環境測量，暖啟動 p95 ≤500ms，首次搜尋 p95 ≤3 秒 |
| 行動版 | 360px 寬度可閱讀，除了表格／程式碼區外無整頁橫向捲動 |
| 韌性 | 搜尋索引載入失敗時可重試，仍能走章節頁閱讀 |
| 可攜性 | Markdown、JSON 分類、圖片及鎖定依賴可完整匯出 |
| 成本 | 一般搜尋無 AI API 呼叫；託管、網域及 GitHub 配額依帳號與官方政策 |

效能數字是驗收目標，不承諾所有裝置／網路皆相同。GitHub Pages 官方目前列出發布網站 1GB 上限、每月 100GB 軟性流量限制；專案內部另設定更小的產物警示值，避免接近平台上限。[GitHub Pages 限制](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)
