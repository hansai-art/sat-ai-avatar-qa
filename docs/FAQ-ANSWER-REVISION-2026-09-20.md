## 逐題內容審查

以下是編輯審查記錄，不是學員實際完成練習的成效測試。

| 問題 | 原答案需補強處 | 本輪可檢查的改變 |
| --- | --- | --- |
| qa-000001 BotFather | 需分開聊天室與模型是否接通 | 指定測試訊息，依桌機與手機回應定位下一步，保留未解追問 |
| qa-000002 Gemini http | 排錯後如何判斷下一步 | 一次改一項，保留新舊錯誤，網址錯誤與授權或額度錯誤分開 |
| qa-000003 費用 | 「先確認方案」缺少整理方式 | 帳號與用途清單、待確認欄位、用現有來源試做再決定是否購買 |
| qa-000004 設備 | 舊設備不能安裝時的練習過於抽象 | 用工作筆記列待辦與原句，將練習方法與檔案操作權限分開 |
| qa-000005 電腦常開 | 需說明何時值得安排常駐主機 | 分別測電腦和手機，按收工前整理或清晨自動工作比較需要 |
| qa-000006 搬家 | 只確認「小任務可驗收」 | 用舊工作資料與認可成果測新環境，分辨路徑、規則、附件缺口 |
| qa-000007 Harness | 抽象元件不易理解 | 訪談材料、語氣規則、文章草稿與原文核對的分工假設 |
| qa-000008 品牌語氣 | 沒有文章時的正反例與成效判斷 | 以喜歡／不喜歡原句形成待確認規則，用新訊息試寫，比較範本替代方案 |
| qa-000009 SEO 概念 | 外掛提醒如何交給 AI | 草稿＋提醒＋讀者問題，提出有依據的改法，不補造保存天數 |
| qa-000010 外掛安裝 | 缺少權限與已裝外掛的分流 | 草稿預覽、前台確認、匯入後抽查原設定，保留官方限制 |
| qa-000011 新手 | 泛稱「先做小任務」 | 筆記轉待辦，原文沒有負責人／期限則待確認，以新筆記重測 |
| qa-000012 Notion | 沒有說明何時匯出或串接 | 同一查找工作比較貼文字、匯出副本、持續串接與維護時間 |
| qa-000013 Heptabase | 小規模移轉仍缺實際核對 | 一張卡片連同附件與關聯，用研究任務檢查遺失，不先承諾無損 |
| qa-000014 n8n | 只列課程邊界 | 比較手動交辦、結構化輸入、自動串接，尚需逐筆判斷時保留人工清單 |
| qa-000015 教材 | 下載後能做什麼 | 讀說明、確認輸入與預期產出，回報缺檔時提供單元與畫面 |
| qa-000016 App | 泛稱「做原型」 | 用明細分類測一個動作，比較試算表、現成工具、互動原型 |
| qa-000017 Token | 縮短輸入不等於降低總成本 | 同一工作比較結果、用量與人工修正時間，不預估省費比例 |
| qa-000018 查核 | 附連結不等於原文支持 | 結論與短摘錄逐項對照，以場地容量假設示範適用條件不能推測 |
| qa-000019 筆記與 Skill | 缺少由經驗整理方法的步驟 | 初稿與定稿拆規則，每條附例句，新材料測試，再比較筆記／範本／Skill |
| qa-000020 一小時 | 容易固定叫學生整理知識庫 | 用自己常查問題測時間與正確性，必要時改用更常做的工作 |
| qa-000021 多 bot | 分開名稱不等於隔離權限 | 先比較單 bot 是否足夠，用無私人內容的小樣本測分工並檢查權限 |
| qa-000022 影片 | 泛稱「定義剪輯規則」 | 成片與原素材拆選片依據，新素材驗候選時間碼，再決定清單／粗剪分工 |
